## 읽는 순서 (토큰 절약)
1. `Grep`으로 장 제목·키워드 위치를 찾고 `Read`의 offset/limit으로 **해당 구간만** 읽는다.
2. 기능 → 기능명세서 해당 장(1~11장). 데이터 → DB명세서 해당 테이블(1-x)·흐름(4-x).
3. 예외·문구 → 전체문서 5-4장(E-01~E-63). Q 항목 → 5-4-10(Q-01~Q-13). Q-01~Q-12의 확정 내용은 CLAUDE.md "확정된 결정" 표.
4. 이미 읽은 내용은 다시 읽지 않는다. 스킬에 요약돼 있으면 그것으로 충분.

## 질문이 필요한 경우 (임의 결정 금지)
- 사용자 의견이 갈리는 중요 결정: 스키마·API 모양, 보안 정책, 기능 범위.
- **미결 Q-13**(벌칙 이행 이전 경고의 이력 표시)과 닿는 코드. Q-01~Q-12는 확정이므로 CLAUDE.md 표대로 구현하고 다시 묻지 않는다.
- 명세에 없는 규칙. (제안)/(추측) 표시된 항목.
- 기획서에 없는 기능·의존성이 필요해 보일 때(기본은 만들지 않고 추가하지 않는다).

질문 형식: 한국어, 선택지 2~3개 + 추천 1개 + 근거(장 번호). 답이 오기 전엔 그 부분만 보류하고 나머지는 진행.
