# 테스트 (기능명세서 5·6·7장 "JUnit", 11장 "판정 테스트")

## 원칙
- JUnit 5 + AssertJ. 테스트 이름은 한국어 서술형: `주_3일_인증과_기록글_1개면_통과한다`.
- **단위**: 순수 규칙(판정 계산, 재계산 알고리즘)은 Spring 컨텍스트 없이. 시간은 `Clock` 주입으로 고정(KST).
- **통합**: `@SpringBootTest` + 기획서의 Docker Compose 로컬 DB(MariaDB·Redis·MongoDB) 기준. 추가 테스트 라이브러리는 넣지 않는다(필요하면 질문).
- 외부(GitHub API)는 fake/stub. 실제 호출 금지.
- 테스트가 실패하면 원인을 보고한다. 테스트를 약하게 고쳐 통과시키지 않는다.

## 반드시 덮을 시나리오
- 판정: 잔디0+기록글 3일 통과 / 같은 날 잔디+글 1일 / 댓글 불인정 / 일요일 23:59 경계 / 첫 참가 주 제외 / 팀 없음 제외 / 여러 팀 1회 판정.
- HOLD: API 실패 시 경고 없음 / 재실행은 HOLD만, 확정 건 skip / 멱등.
- 경고: 미달 1개(팀 N:M) / 2주 연속 통과 차감 후 연속 0 / 3회 차감 중지 / 이행 후 0 / 추방·팀삭제 카테고리 제거 / 자진 탈퇴 유지.
- 재계산: 정정·소급 면제 순서가 바뀌어도 같은 결과 / 면제 주는 연속을 끊지도 늘리지도 않음 / 이행 이전 주차 정정은 기록만(E-58, E-59) / 삭제된 경고가 되살아나지 않음(E-60) / 미리보기는 무변경.
- 팀: 추방자 초대코드 차단 1년, 아이디 초대 허용 / 팀장 위임 후 탈퇴 / 팀 삭제 시 글 유지.
- 권한: 각 Mutation의 403.

## 미결 항목 테스트 금지
Q-13처럼 결론 없는 규칙과 기획서에 없는 동작은 기대값을 임의로 정해 테스트하지 않는다. 질문 후 작성.
Q-01~Q-12는 확정이므로 CLAUDE.md 결정 표대로 테스트한다.

## 실행
`./gradlew test` (wrapper). 결과는 통과/실패 수와 실패 원인만 짧게 보고.
